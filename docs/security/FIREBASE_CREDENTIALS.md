# Firebase Admin Initialization Without Credential Files

## Overview

Traditional Firebase tutorials often advise developers to download a `serviceAccountKey.json` file and point the SDK to it using file paths. This practice creates severe security risks, including accidental git commits and compromised infrastructure credentials.

ProjuktiX implements **in-memory, environment-based Firebase Admin SDK initialization**. No JSON files or persistent keys ever touch the local filesystem or container disk.

---

## 1. How the In-Memory SDK Works

In `apps/api/src/config/firebase.ts`, the initialization logic parses credentials directly from environment variables:

```typescript
import { initializeApp, cert, getApps } from 'firebase-admin/app';
import { getFirestore } from 'firebase-admin/firestore';
import { getAuth } from 'firebase-admin/auth';

export function initializeFirebaseServices() {
  if (getApps().length === 0) {
    const projectId = process.env.FIREBASE_PROJECT_ID;
    const clientEmail = process.env.FIREBASE_CLIENT_EMAIL;
    const rawKey = process.env.FIREBASE_PRIVATE_KEY;

    if (projectId && clientEmail && rawKey) {
      // Normalize private key newline formatting
      const privateKey = rawKey.includes('\\n')
        ? rawKey.replace(/\\n/g, '\n')
        : rawKey;

      initializeApp({
        credential: cert({
          projectId,
          clientEmail,
          privateKey,
        }),
      });
    } else {
      // Fallback to Application Default Credentials or Local Emulator
      initializeApp();
    }
  }

  return {
    firestore: getFirestore(),
    auth: getAuth(),
  };
}
```

---

## 2. Formatting the Private Key

Google Cloud service account private keys contain newlines. When setting `FIREBASE_PRIVATE_KEY` in cloud consoles (like Render) or shell sessions:

- In Render Dashboard: Paste the exact multi-line private key as generated by GCP (including `-----BEGIN PRIVATE KEY-----` and `-----END PRIVATE KEY-----`).
- In Terminal export: You can use `\n` representation:
  ```bash
  export FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvgIBADANBgk...==\n-----END PRIVATE KEY-----\n"
  ```
The code automatically handles both formatted and escaped newline characters.

---

## 3. Local Development with Emulators

For zero-cloud local development, you do not need Google Cloud credentials at all. Simply run the Firebase emulator suite:

```bash
firebase emulators:start --only firestore,auth
```

And in your terminal:
```bash
export FIRESTORE_EMULATOR_HOST="127.0.0.1:8080"
export FIREBASE_AUTH_EMULATOR_HOST="127.0.0.1:9099"
pnpm dev
```
The Firebase Admin SDK automatically detects these standard environment flags and routes all traffic to the local emulator without validating cryptographic signatures.
